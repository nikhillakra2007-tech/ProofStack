## P16. Green-but-dead tests (test theatre)

**Tier 3 | CORR (testing integrity) | probe `p16_mutation.py` | gate G3 | class B target: source file + test command**

**Failure mechanics and root cause.** AI-generated tests often assert nothing useful: `assert True`, `is not None`, a snapshot of the implementation's own output, or a mock of the unit under test. They keep the suite green and the coverage number high while the function is broken. A patch accepted on "all tests pass" is then unverified.

**Field evidence.** Mutation testing is the established remedy: "State of Mutation Testing at Google" (Petrovic and Ivankovic, ICSE-SEIP 2018) describes it at scale, and Meta has published on mutation-guided LLM test generation (2025). Tools: `mutmut`, `cosmic-ray`. Equivalent mutants make a 100% kill rate unattainable, hence a threshold below 1.

**Red-state probe.** One AST mutation at a time (comparison swaps and boundary shifts, arithmetic and boolean operator swaps, constant and boolean flips, `return` to `None`, condition negation) applied to a throw-away copy of the project; the suite is rerun with a timeout; a failing or timed-out run kills the mutant. The baseline suite must pass first. Fewer than 10 mutation sites yields `INCONCLUSIVE`.

## P17. Multi-resource database deadlock ordering

**Tier 3 | CONC | CWE-833 | probe `p17_deadlock.py` | gate G5 | target module: `transfer(src, dst)`**

**Failure mechanics and root cause.** Two transactions that take the same two locks in opposite order wait for each other forever (or until the database aborts one). A transfer function that locks `src` then `dst` is correct for one caller and deadlocks when A-to-B and B-to-A overlap. Tests run one transfer at a time.

**Field evidence.** The PostgreSQL manual (explicit locking, deadlocks) states that the best defence is acquiring locks on multiple objects in a consistent order. SQLSTATE note: PostgreSQL reports a deadlock as `40P01` (`deadlock_detected`) and a serialization conflict as `40001`; MySQL/InnoDB reports a deadlock as error 1213 with SQLSTATE `40001`; SQL Server uses error 1205. The checklist cites `40001`; the probe therefore treats `40P01`, `40001`, and errno 1213/1205 as deadlock evidence. Retry-on-deadlock is a safety net, not the fix.

**Red-state probe.** A fresh module per round; `Lockstep` forces the opposing-order interleavings for three schedules (pair A-B/B-A, triangle A-B/B-C/C-A, fan-out). Red when any worker is still blocked after a 2 s deadline, or a database deadlock error code is raised. Database-backed variant: run the same schedules against a sandbox-local PostgreSQL with two connections and catch `psycopg.errors.DeadlockDetected`; the probe already inspects `sqlstate`/`pgcode`.

## P18. Distributed multi-service contract drift

**Tier 3 | CORR (integration) | probe `p18_contract_drift.py` | gate G3 | class B target: two JSON Schemas plus example payloads**

**Failure mechanics and root cause.** A type, enum or required-field change in one service silently breaks downstream consumers that were never deployed with it. Each service's own tests pass. AI refactors rename fields, tighten types, or add enum values without seeing the consumers.

**Field evidence.** Consumer-driven contract testing (Pact), schema-registry compatibility modes (BACKWARD, FORWARD, FULL in Confluent Schema Registry), and diff tools such as `oasdiff` (OpenAPI) and `buf breaking` (protobuf) exist because this is the dominant integration failure. Practice: additive changes, expand-contract migrations, tolerant readers.

**Red-state probe.** Direction-aware structural rules plus example cross-validation. BACKWARD: data written under OLD must validate under NEW. FORWARD: data written under NEW must validate under OLD. FULL: both. Violations include type changes, removed or newly required fields, enum widening seen by an old reader, and `additionalProperties: false` conflicts. Limitation: `$ref` must be pre-resolved.

## P19. Float-based money arithmetic and rounding drift

**Tier 3 | CORR (ledger) | CWE-681, CWE-1339 | probe `p19_float_money.py` | gate G3 | target module: `total`, `tax_lines`**

**Failure mechanics and root cause.** Binary floating point cannot represent most decimal cents. Summing and rounding per line produces cent-level discrepancies that accumulate over large batches; mid-point cases (an exact half cent) round the wrong way in a binary representation. Reviewers see correct-looking totals on small examples.

**Field evidence.** The Python `decimal` documentation exists for this reason; the Vancouver Stock Exchange index lost roughly half its value on paper between 1982 and 1983 because of truncation at every update (a rounding-drift classic); the 1991 Patriot clock error shows how tiny representation error accumulates. Practice: integer minor units or `Decimal` with an explicit exponent, rounding mode declared by policy, never `float`, `NUMERIC`/`BIGINT` in storage.

**Red-state probe.** A golden ledger of 100,000 seeded cent amounts. The exact reference is `Decimal` with the declared rounding mode (default `ROUND_HALF_UP`, overridable per jurisdiction). Red when the total is off by one cent or more, any per-line tax differs, or the result is a `float`.
